# 3D 自然输入资格审计（2026-10-25）

本目录只归档已有 **pre-GP 结构导出** 的简要证据，没有重新运行 GP、布局、布线或 GNN。原始网表、完整逻辑图及大型位置列表保留在 WSL；每个设计的 `source_file_index.json` 记录其路径、大小和 SHA256。历史输入审计保持原样，模式修正的结果单列在 `mode_aware_addendum.json`。

冻结的 DSP 模式解释器确认：这批 `multiply` 都采用 27×27 → 54 位模式，每个原语占两个最小 DSP 模式单位。因此资源需求更新如下（顺序为 LUT、FF、RAM、DSP 模式单位、IO）：

| 设计 | 更新后需求 | 物理 RAM APBlock | 物理 DSP APBlock |
| --- | --- | ---: | ---: |
| SHA | 1811, 893, 0, 0, 74 | 0 | 0 |
| OR1200 | 3348, 672, 4, 8, 747 | 4 | 4 |
| SPMV | 9346, 4009, 232, 64, 99 | 232 | 32 |
| BGM | 30272, 5105, 0, 22, 289 | 0 | 11 |

**重/轻分组按物理 hard APBlock 数量判断，不按模式单位数量判断。** BGM 仍只有 11 个 DSP APBlock，不能因模式需求变成 22 就改称第二个 heavy 设计；OR1200 仍为 8 个 hard APBlock。SPMV 为当前合格的 heavy 输入。其余第二 heavy 设计的有限综合探测见相邻 `v7_heavy_input_probe_20261025`，MCML 在固定 120 秒综合预算内超时，需求未知，尚不能宣称四个预定设计族均已就绪。

`independent_audit.json` 记录原 2D/base 与 v6.8 二进制哈希保持一致、新 3D 后端版本命令成功，以及本轮精确目录回收账目。TERM/INT 的短时子进程测试验证取消后只终止本工具创建的进程组、保留 interrupted 尝试、阻止新派发，并可在新 Python 进程中恢复。SIGKILL 无法由 Python 捕获，需要调度器清理同一作业内的剩余进程。

本目录的结果证明输入解析及恢复约定可用，不是 GNN 性能验收，也没有证明运行时间或布线质量收益。

## 1. 唯一主目标与最终交付

**训练一个真正的 3D 初始化生成器，学习资源兼容的层分配和层内初值，在成功率不下降、五 seed 平均 Wmin / CPD / WL 退化均不超过 3% 的条件下，使计入初始化成本的总 runtime 至少降低 5%。** 开发 pilot 与冻结后的未见族测试分别报告，不能把开发选择结果当作最终泛化证据。

主路线固定为：

```text
网表 → prepack / APBlock 图 ─────────────┐
                                       ├→ 训练后的双图 GNN
架构 + 真实 RRG → 分层区域／共享资源池图 ┘
    → APBlock 联合选择 (layer, XY 区域) + 区域内连续 XY
    → 层兼容与必要容量上界检查 + 快速区域/XY 输出
    → 有限 XY 密度修正（无额外风险局部搜索）
    → init.ap.tsv 温启动原生 3D GP
    → APPack → VPR 详细退火 → route / analysis
```

最终交付是可部署的 checkpoint、完整数据和后端版本、可复现评测及按功能归因的结果。不是一个新的启发式布局器，也不是“成功写出 `.fplace`”或“代理指标下降”的演示。

### 本轮明确不做

- 不重启 TailRisk 单指标机制验证、自动分组算法优化或合成热点造数项目。
- 不继续把旧 packed-cluster 贪心初值、几何时序保护、退火温度／局部半径调优作为主目标。
- 不从头开发 3D placer，不强制引入 TritonPart、LaZagna、Beyond Flatland 才能开始。
- 不把 3D 训练成功、接口成功、最终性能成功混为同一个验收。
- 不以增加层数、增加数据、增加候选数来无限延期对当前方法的判断。

## 2. 已有事实、需要补齐的接口及研究范围

### 2.1 继承什么，不能冒充什么

| 项目 | 当前事实 | 本轮处理 |
|---|---|---|
| 2D v6.8/v6.9 逻辑单元 | GP 前 APBlock，保留 molecule / RAM-group 原子性 | 继承逻辑对象及已验收接口 |
| 分层物理区域 | **每层每 4×4 个 tile 一个叶区域**，不是整个器件只有 4×4 区域 | 面积增加时增加叶节点；扩展 layer、层次边和真实垂直共享池 |
| 已有 3D pilot | packed-cluster 初值／修正后走 SA；尚无训练后的 3D GNN | 保留为历史基线，不当作学习主线成果 |
| 固定 VTR 源码 | 有 XYZ B2B 求解、多层密度／partial legalization；APPack 传递 layer | 优先验收这条原生路径，而非另造逐层 2D GP |
| 当前 2D 数据、输出和 hook | 显式限制 layer=0／单层；模型只有 XY 输出 | 新建隔离 3D 版本，扩展 schema、联合区域选择和注入校验 |
| 异构层补丁 | 已通过限定范围的 SA/P&R 和 2D 回归 | 复用正确性修复，但 GP→APPack 全链仍需独立资格验收 |
| `.fplace` / `.place` 回读 | 已有成功例 | 不能替代 GP warm-start 验收；`--read_flat_place` 会绕过 GP |

源码核查的特别说明：`NaiveFullLegalizer` 的 layer=0 断言不代表 `APPack` 没有多层实现。源码路径存在，也不等于我们的异构多层学习初值已经端到端通过。

### 2.2 v6.9 已完成的证据与需要迁移的经验

已同步并重算的 2D 记录包括 640 次 feedback、320 次宽度扫描和 80 次受控并行计时。四个测试设计等权几何平均，计入初始化总时间增加 38.01%，纯 VPR 时间增加 2.66%；40 个计时条件中 Default 成功 40 个、Fast 成功 34 个，整体性能验收未通过。

局部证据仍保留：LU8PEEng/w180 五个 seeds 的总时间都下降，几何平均为 −3.36%，CPD +1.67%、WL +3.23%，未达到原定组合门槛；spree 五 seed 平均已测 Wmin 从 92.0 降到 90.4，但一次触及扫描下界。训练候选 bnn/w200/c3、lenet/w200/c0 的总时间下降 5.67%、22.52%，是训练集事后筛选，不能充当未见设计收益。

据此作以下实现调整：

- 解码中位数约 0.005–0.256 秒，快速生成的工程目标已经实现。函数外启动/导入/签名及包装 IO 仍约 1.5–2.4 秒，对小设计影响很大，需分别报告冷启动和常驻服务成本；不能把它们全部归因于某个 import。
- 后续 GP 和布线工作没有稳定减少，去掉启动开销也不足以证明方法有效。3D 必须同时记录实际阶段时间和迭代量。
- 软密度后独立 argmax 仍可能集中需求：LU/w156 约 47.8% 的 LUT 需求落在一个叶区域、84.2% 落在前三个。该统计只是 AP 需求/容量代理，不能据此判最终物理放置非法；但层级解码必须保护资源兼容和层总容量，不能原样复制两轮软调价后独立 argmax。
- 160 个训练条件中仅两个替换成真实收益初值，其余仍主要用原教师监督；被拒绝候选未直接作为负收益训练信号。最佳验证 epoch=1，checkpoint 仍按教师重建 loss 选择。因此是有效 runtime 监督稀疏且选模目标不对齐，不能误写为“只有两个训练样本”，也不能把 640 次 VPR 等同于 640 个有效 runtime 目标。

证据入口见第 13 节。2D 的工程验收与性能未通过必须同时进入 3D release manifest。

### 2.3 后端和兼容性冻结

- 基础 VTR commit：`40f8d19708b0b60e2aa04452deb1cfed68d96b0b`，与当前 2D/服务器口径一致；不切回历史 `e422b08`。
- 新 3D 安装采用“该 commit + 已审计的 heterogeneity v2 补丁 + 新 3D warm-start hook”的精确补丁清单与二进制哈希。
- v2 已包含 v1，不重复叠加。现有观测、local proposal、温度实验补丁不默认并入性能路径。
- 不直接放宽 v6.8 安装器的 dirty-tree 检查。新安装器审核组合补丁，旧 2D 安装、数据、checkpoint 和验收脚本不变。
- 单层模式保持旧字段语义；新 schema 显式版本化。相同旧输入／权重在兼容模式下应保持原行为，新训练的 3D 模型不要求天然等于旧 checkpoint。
- 主阶段使用双层、同一个 architecture XML 中定义的 tile/primitives。层间资源数量和位置可以不同；不研究跨层不同 primitive 定义。
- 多高度 hard block、placement macro、混合硬资源 APBlock 等，仅纳入已明确支持并通过资格测试的范围；不支持项显式拒绝，不压成单一资源类型。

## 3. 功能边界：每个模块到底负责什么

| 功能 | 输入 → 输出 | 可以保证／检验什么 | 不能声称什么 |
|---|---|---|---|
| APBlock 图 | prepack 结构 → 节点、超边、需求、固定约束 | molecule 完整、训练／部署对象一致 | 已经完成 packing |
| 真实 RRG 区域图 | RR nodes/edges → XYZ 共享池、方向、segment、容量 | 不把共享 wire 重复计数；保留已知零供给与连通性 | 粗区域可达就等于 pin-level 一定可布通 |
| GNN | 逻辑图 + 器件图 → 联合区域分数、XY | 可学习的层／区域／坐标初值 | 硬合法布局或时序保证 |
| 快速解码器 | 分数 + mask + 五维需求代理 → 初始层/区域/XY | 检查固定节点、molecule 原子性、层兼容及必要层容量上界；报告叶区域密度溢出 | 真实 packing、macro 或详细 site 合法性证明；软密度不保证各叶区域零溢出 |
| 有限密度修正 | 初始 XY → 有限调整后的 XY | 减少明显区域集中，记录预算、溢出及全部实际耗时 | 以代理风险做移动/交换搜索，或保证最终 QoR |
| warm-start hook | AP 初值 → 原生 solver 状态 | 初值真的被消费，原生 GP 继续执行 | 初值必须被后端保持不动 |
| GP/APPack/SA/router | 初值与真实架构 → `.net/.place/.route` | 实际 packing、位置与路由检查及 QoR | 后端成功足以证明 GNN 优于 Default |

Layer prior 直接来自 **训练后的 APBlock→(layer, leaf) 联合选择**。首版不增加独立连续 Z 回归 head：选择叶区域时得到离散初始 layer，XY head 在叶区域内给连续坐标。原生 GP 后续仍可优化连续 Z，合法化再映射到实际层。

所有方法的 layer prior 都是软初值，只有真正的 fixed/floorplan 约束是硬约束。不因初始化被改动就锁层；“锁层”会改变后端搜索空间，需要另立协议，不能偷偷加入。

| 阶段 | 核心目标 | 可并行工作 | 交付与通过条件 | 停止／转向规则 |
|---|---|---|---|---|
| P0：接收 2D | 冻结 v6.9 工程契约和真实正负结果 | 数据暴露名单、架构清单、预算设计 | release/patch/checkpoint/schema 哈希；工程与性能验收分开；分族与指标冻结 | 不以 2D 整体性能为 3D 开工前提，不把负结果改写为性能通过 |

| P4：冻结测试 | 在未参与训练／选择的族上一次性评测 | 所有预登记方法和架构任务 | 完整成功/失败记录、配对统计、泛化和计时报告 | 测试结果不回流调参；若需新方法，另建版本及新测试协议 |
| P5：结论与扩展决策 | 判断最终方法有效、何时有效、谁起作用 | 报告、复现实验包、外部方法可比性检查 | 回答第 11 节的预登记问题 | 不要求每个模块都正收益；三层/更多架构不是失败后的补救任务 |

### P1 的有限验收包

计划最多 24 次核心资格 P&R：4 个预登记 case × 3 个入口（Default、初值 A、初值 B）× 2 seeds，另运行已有 2D 回归和输入单测。case 覆盖同构双层、异构双层、CLB/DSP/BRAM 与固定层、至少一个非微型开发设计；必须有需要实际跨层连接的例子。

初值 A/B 可来自开发集 native GP 回放及明确改变层的合法输入，只用于检验接口，不计作学习效果。第一次失败只定位实现错误，不调 QoR；以两轮修复／约两个工作日工程预算为检查点，超出后先出阻塞报告与范围决策。

必须保存并检查：

1. APBlock→atom 完整覆盖、同 molecule 同坐标，fixed XYZ 不变，非法 layer 被拒绝。
2. 初值 checksum 包含 XYZ；A/B 的非零 layer 确实进入 solver。
3. 日志具有 `GP_INIT_CONSUMED` 与 `NATIVE_SOLVER_CONTINUED iteration=1` 的可验证证据；没有 `--read_flat_place` 旁路。
4. init、post-GP、post-APPack、post-SA 的层分布及坐标；最终 `.place` 和路由检查通过。
5. 跨层网络实际使用垂直路由资源，不只是在 layer 1 放了节点。
6. APPack 前后器件 grid/容量一致；各方法强制使用同一器件，禁止因重新 packing 自动换成不同尺寸。
7. 原 2D 安装不变；单层兼容路径与原验收结果一致。

通过后冻结后端，后续只修可复现 correctness bug。修复若改变行为，相关实验按新 backend hash 整组重跑，不能混入旧表。

## 5. 数据与架构：在运行方法之前确定难度

### 5.1 设计族划分与覆盖

继承当前 `tailcompile_v68/cohort.json` 的候选清单，且服从 **2D+3D 全历史暴露记录**：

| 划分 | 候选数量 | 用途 |
|---|---:|---|
| train | 20 | 教师、真实反馈、模型和工程调试；SHA/OR1200 等既有 3D pilot 只能在此 |
| validation | 3：blob_merge、diffeq、softmax | 按真实 VPR 收益与保护规则选择 checkpoint／密度配置，教师 loss 只作诊断；首轮无风险局部搜索 |
| inherited holdout | 4：arm_core、spree、mkPktMerge、LU | 其 2D v6.8/v6.9 结果已经被查看，只作跨版本跟踪或开发证据，不能命名为全历史未见最终测试 |

数量是候选数，不代表全部已通过 3D 工具资格。参数变体、随机 seed、候选布局、不同 architecture 一律随设计族绑定划分。任何进入 2D 预训练的家族不得重新划入“3D 未见测试”。

首批开发 pilot 从 train/validation 中预先选择四个族：两个 DSP/BRAM 使用较重、两个较轻的控制。选择依据输入资源统计、来源独立性和工具资格，不能依据哪组方法获胜；若从 validation 选开发族，明确其后不再是最终未见测试。SHA/OR1200 可以作接口控制，但不能仅靠硬资源使用很少的设计检验异构层优势。

冻结模型后另用全历史未参与开发的设计族做最终测试。同步盘点 `bwave_like.fixed.small`、`dla_like.small`、`tdarknet_like.small`、`mkSMAdapter4B` 等新增来源，**先审核来源与历史暴露，再决定其资格及独立性**。目前只确认文件存在，不保证可综合、受支持或未见。最终名单在查看方法效果前封存；数量不足时报告样本局限，不用更多 seeds 冒充独立设计，也不预先承诺恰好八个未见族。

资格排除只依据预定原语/结构支持范围、文件损坏、全局容量及工具基础兼容性。进入正式范围后某方法解码、packing 或路由失败，属于方法结果，不因此删掉设计。资格失败与全方法都难布通也不能混为一谈。

### 5.2 主架构四格：H × Z

| 因子 | 水平 0 | 水平 1 | 配对要求 |
|---|---|---|---|
| H：层资源分布 | 两层对称 | 两层 DSP/BRAM/CLB 数量或位置不对称 | 相同 XML primitive、grid、全局各资源总量、IO 和 routing 定义 |
| Z：垂直供给位置 | 均匀 | 集中 | 真实独立 Z 资源池总供给及方向/segment/switch 类别预算相同，仅改变位置 |

形成 `H0Z0/H0Z1/H1Z0/H1Z1`。H 优先复用现有匹配构造：同位置硬资源列、每层 2 DSP+2 RAM 对比 3 DSP+1 RAM / 1 DSP+3 RAM。总量相同不代表所有 pin access 完全相同，差异必须留在真实 RRG 审计中。

Z 位置与密度分开：首批只运行 D=100% 的四格；**D=50% 垂直供给** 作为后续可选密度泛化面板，在首批验证后另行冻结预算。集中位置按固定几何规则选定，不参考设计热点；对称移动的额外位置也不临时加到本轮结论。

现有 `pilot_architectures.py` 尚未实现完整 Z 位置/密度变化。这是 P1/P2 的架构生成任务，不能把现有 H 配对称为已完成 H×Z 配对。需要真实 RRG 检验：

- 按共享 wire/node pool 去重，不能拿跨层 edge 数当容量；分别核对方向与 segment 类别。
- 每个测试 channel width 均重新核对。若 width 同时改变 Z 总供给，记录耦合量；只有验证解耦后才能声称“单独改变横向资源”。
- 同一条件所有方法读同一 architecture/RRG，device dimensions 固定；文件哈希列入任务签名。
- 若工具不能实现等容量的 Z 位置配对，在训练前修订架构协议或把 Z 位置因果问题标为未具备条件；不能用“更集中且更稀少”代替，也不宣称 Z 位置效应。

### 5.3 channel width 与 seed

宽度只用 Default 和独立 calibration seeds 确定，不能看某个模型在哪个宽度获益后再选。

- 预登记候选宽度网格：`32,48,64,80,96,128,160,224,320,448`，均须通过架构宽度合法性检查；若架构要求其他步长，在模型评测前生成等价合法网格并冻结。
- 每个 design 的 D=100% 四种主架构，按固定网格顺序采集 Default 两个校准 seed；每架构最多 20 次尝试，已找到共同参考点与压力点即可停止。已有完全相同签名的 Default 结果可缓存复用。
- **同一个 design 的四种 H/Z 架构共用两个宽度**，不逐架构选不同难度的宽度。`W_ref` 是网格上第一个四架构×两 seeds 共 8/8 正常布通的点；`W_stress` 在更小且至少有一个正常不可布通的点中，选择这八次运行成功率最接近 50% 的点，平局取较大宽度。这样 H/Z 对比不混入横向通道宽度变化；有的单格更难、有的更易是架构因素本身的结果。
- 如果没有更小失败点或找不到共同 `W_ref`，标记左/右删失；只允许一次 **Default-only** 网格扩展并在方法运行前冻结。仍无边界则保留为非边界/删失样本，不伪造压力点或按模型收益换设计。环境错误/超时不作为“正常不可布通”来定位边界。
- 若以后执行 D=50% 面板，复用该 design 在 D=100% 确定的两个宽度，不重新调宽度抵消 Z 容量下降；全失败也完整记录。
- 正式同一条件内各方法使用完全相同宽度、backend seed、器件和时间预算。两宽度不是两个独立设计。
- 如观察到非单调布通，应保留完整状态，不硬拟合成严格阈值。

|---|---|---|
| 工程资格 | 701/702 | P1 初值消费与原生 3D GP/APPack 资格，不用于性能选模 |
| calibration | 501/502 | Default-only 宽度和固定资源预算校准 |
| teacher | 511/512 | train 原生 GP 教师；validation 标签只作验证 |

两固定宽度只服务 pilot 的压力点成功率及配对 runtime，**不能据此计算可靠平均 Wmin**。Wmin 另建边界扫描任务：仅凭 Default 校准结果，在方法评测前冻结同一 design 四架构、全部方法共用的合法细化网格；五个评价 seeds 都扫描完整网格，不因某方法首个成功而提前停止。评价 seed 与阶段相符，开发用 531–535，最终用 541–545。

对方法 m、seed s 定义 `Wmin_grid(m,s)=min{w∈G: status(m,s,w)=success}`，主宽度统计是五个 `Wmin_grid` 的算术平均。若无成功、最低点已成功、或未知结果可能改变最小值，分别记录右删失、左删失和未知，不填零、不用扫描上界冒充成功值，也不只平均较好 seeds。只在五 seed 可比性明确时计算宽度退化比，否则宽度保护为未完成。各宽度重新走 GP/packing/P&R，所得是该流程的已测资源需求代理，不是固定布局的物理路由阈值；非单调状态原样保留。

## 6. 3D 模型和训练：直接训练部署的生成器

### 6.1 固定接口，不扩张成另一个布局算法

- 逻辑节点沿用 APBlock；超边、fixed 信息、五维需求与全局网处理沿用验收版语义。
- 器件叶区域 ID 显式编码 `(layer, x_leaf, y_leaf)`，每层每 4×4 tile；XY 层次、层间真实 RRG 连接和共享池共同编码。
- region logits 联合选择 layer 与 XY leaf，稀疏 top-k/分块解码；不建立 APBlock×全部物理 site 的稠密矩阵。
- XY head 在选定叶内产生连续 XY，`init.ap.tsv` 展开成 atom 行；离散初始 layer 取叶区域 layer。它不是最终 site placement。
- 固定层/资源 mask、fixed XYZ 和 molecule 原子性是必要约束；层级联合分配还检查模型覆盖的逐层 LUT/FF/硬资源需求上界。不要将所有区域按比例精确均摊，也不把区域需求代理误称真实 packing 合法性。
- 层内 XY 采用快速输出及有预算的密度修正，显式记录使用区域数、分资源的需求集中度与溢出。不能只做两轮软调价再独立 argmax 就声称层容量得到保证；也不恢复对全体叶区域的昂贵精确 packing 解码。层级容量冲突应做有限修复或显式失败/回退，不能增大容量掩盖。
- 供给图上的粗可达性用于筛查已知不可行，不冒充完整 pin/switch 可达证明。无兼容层或已知零供给不可达时显式报告。
- 新输入维度、Z 模块及权重迁移有显式映射；只拷贝含义和形状匹配的 2D 权重，记录新增参数初始化。不能把旧二维 checkpoint 直接换名称当成 3D 模型。

### 6.2 教师锚点与真实收益反馈共同训练生成器

1. 先用 train 的原生 3D GP 教师训练 layer/region/XY，验证输入对象和部署一致。每个 condition/seed 保存一个完整解，不平均对称或互相冲突的层/坐标。validation 教师不参与梯度，final 不提供 movable teacher 坐标。
2. 原始 GP XYZ 与资源兼容投影标签分开。raw Z 按冻结版本 native density/legalizer 的映射规则转为离散 layer，以边界、半整数、越界测试核对，不依赖 Python 默认舍入。资源投影使用固定字典序：先最少层改变，再最小 XY tile 距离，fixed 不动。保存 `raw_z→mapped_layer→projected_layer`、XY 位移、层跳数、需求溢出和派生哈希；不把一层等同一 tile 物理距离。投影仍不是 packing 合法化。
3. 真实反馈直接服务部署生成器。每个训练 condition 生成四个候选，包含一个确定性输出和三个按冻结噪声/采样规则产生的候选；无风险局部搜索。用 521/522 两 seeds 运行相同 native GP/APPack/SA/router，并采集同条件 Default 锚点。
4. **保留全部候选的正面、负面、正常失败及超时状态。** 按相同 condition 的候选间以及相对 Default 的总耗时/QoR 差异，形成收益方向和偏好监督；通过预算的高质量候选也可作为加权坐标/层目标。不能再次只保留两个赢家，其余直接丢弃，也不能把教师重建训练重新命名为 runtime 优化。
5. 更新实际 layer/region/XY 生成器：教师监督作为稳定锚点，收益监督及其到生成器的梯度/加权蒸馏路径须在实现中明确。VPR 不可微，不宣称梯度直接穿过 VPR；若用代理/排序辅助头，它必须连到生成器更新且单独报告训练作用，不能只训练评分器。失败与 timeout 不填造假的短 runtime 或无限惩罚值；采用显式成功/可比性 mask 和冻结的失败处理规则。
6. checkpoint 使用 validation 的真实 VPR 总时间与成功/QoR 保护联合选择，教师重建 loss 仅作训练诊断。P0 预登记最多三个 checkpoint 候选、对应验证条件和种子，先筛出满足保护的候选，再按设计等权总时间比最低、CPD 比更低、epoch 更早的顺序确定；没有候选通过就记录未达成，不在 final 挑模型。
7. 最终每个方法/条件只允许一次确定性生成；测试阶段没有 best-of-N、结果挑选或先获取 Default 教师布局。常驻服务可以缓存固定器件/模型，但不得读取该测试条件的 movable 教师坐标或路由结果。

反馈覆盖所有已通过 3D 资格的 train 族，在四种主架构、两个 Default 校准宽度分别采样。归一化、预算、权重、训练步数和反馈一轮上限先冻结；资格失败的族依据支持范围处理，不根据方法收益替换。每次报告候选数、可比较配对数、有效收益监督数及每族分布，不能用 P&R 总次数冒充独立训练样本或有效 runtime 目标。

最多两批预登记学习配置；第二批应针对已定位的训练/解码问题，不自动扩大模型和候选数。训练集未能学出合理初值时先解决目标/解码，再判断泛化不足；首次形成完整三组开发结果后再决定是否值得追加研究。

### 7.3 保留但推迟的归因扩展

2026-10-23 初稿的 R/T 四模型 × C0/Cμ/Cτ、L（固定层 prior）、I（2D 权重迁移）及 D=50% 面板，保留为**可选后续研究**，不再是首轮任务或 3D 开工门槛。原 14 臂与 2,112/2,304 次测试、2,048 次反馈数字均不再表示当前派发预算。

若三组主比较已有稳定收益，再在冻结新协议后选择最必要的归因：

- R：比较学习式共享池/RRG 拓扑与保留真实容量/方向/segment 的非拓扑编码。不能通过删除资源兼容性构造弱基线。
- T：明确冻结局部尾部字段及分位数/全局网规则，检验显式输入的增量；局部 P95/P99 与最早分组 cut-pressure TailRisk Profile 不是同一定义。
- L：相同训练预算下比较联合学习 layer 与资源感知固定初始 prior，目标必须满足各自 mask；推理时强行覆盖 layer 不等于公平重训。
- I：只迁移含义与形状兼容的 2D 权重，对比随机初始化，记录共同历史暴露，不宣称天然更优。
- C：若重新引入风险搜索，共用相同候选动作和代理规则，区分平均/尾部目标。沿用明确上限（128 次评价、5 秒检查预算、32 次无改进、1024 次提案）及含初始化/最终校验的 30 秒外层 deadline；超时返回已校验初值并计入全部成本。几何关键网项不是 STA 保护。

上述未执行时，不声称已经证明 Tail/RRG/layer 或迁移的独立因果贡献；当前主问题是最终初始化系统是否有效。后端也不作为自由变量；若必须修改后端，先为 Default 和方法共同更新签名与验证，不能只改方法端再归因给 GNN。

### 8.2 CPU/GPU 分阶段、受控并行和续跑

1. 资格、schema 单测、H/Z 审计及评测器可并行。backend/architecture hash 冻结后才批量采集标签。CPU 完成教师、候选生成和 P&R；GPU 实例只派发训练等 GPU 工作，阶段间原子产物交接。
2. CPU 吞吐默认目标 **32 并发，可配置 16/32 或更高**；按物理核、CPU 配额、实测峰值 RSS 与内存/磁盘余量确定实际值，记录降并发理由。每个 VPR 固定一 worker，避免嵌套线程超卖。大 RRG 解析按预算单独限制，不把 RRG 并发 1 当算法限制，也不无依据地永久沿用 prepare=2。
3. 候选生成也用独立进程池并复用模型/器件编码，不出现 VPR jobs=32 而前端长期串行。常驻推理必须记录模型/器件载入与缓存摊销，固定测试输入顺序及请求成本。
4. 各任务独立 scratch，manifest/metrics 原子写入。断点跳过必须同时满足完整签名和验收状态；成功及正常不可布通可复用。timeout 作为已完成预算结果保留；若提高预算重试，创建新 attempt 并对配对方法同等处理。基础设施/配额故障先修复再有界重试，不能把已成功 case 清空重跑。
5. 默认所有服务器产物放在用户指定的 `/inspire/hdd/project/project-public/changshunjie-253114010247/changshunjie-253114010247/workspace/DAC2027/` 内；scratch、日志、缓存、临时文件通过显式参数指定。跨系统归档保留源码和轻量证据，大 RRG/中间文件按哈希索引，不强制入 Git。
6. 记录 CPU/GPU/存储预算并设置剩余空间预检。已结束运行的派生 `.net`、`.net_postrouting`、`.net.post_routing`、重复 RRG、`.route` 可在**指标持久化且依赖审计确认不再用作 pack 输入/教师/回放**后回收；输入网表、共享 packed-net、模型/IR/标签/日志、初值和时间证据保留。文件扩展名不能单独决定删除，活动目录和未完成结果跳过；清理先计划、应用留账。

### 8.3 runtime 的公平计时契约

正式 runtime 采用受控并行配对：每个 VPR 一个物理核，避开同核超线程；同一 (design, architecture, width, seed) 的三方法先后绑定同一核，以 A=Default、B=capacity-only、C=GNN 轮换 ABC/ACB/BAC/BCA/CAB/CBA，两个方法的子实验交替 A→B/B→A。同波同步启动，固定实际并发和线程数，记录 host/boot、CPU quota、affinity、内存限制、任务顺序。不同并发或串行结果独立统计，不能拼接一个加速比；不足整波的尾波单列负载。

主时间包含每次推理、层/区域解码、有限密度修正、文件生成和后续全部 VPR；进程启动、模型载入及请求包装不能消失在计时边界外。**P0 默认冻结单次冷启动总成本为主验收口径**；常驻服务作为独立部署面板，记录服务初始化、请求次数与摊销规则，各自与相同条件 Default 配对。若研究实际部署就是常驻服务，须在方法结果产生前更改协议并明确主口径，不能事后挑较好者。RRG 提取/编码和其他可复用器件成本单列冷成本、缓存命中、摊销次数，不能把特定设计的工作伪称器件缓存。

GP、APPack/完整合法化、详细布局、路由的墙钟与 CPU 时间、CG/放置/路由迭代量分别记录。失败耗时、超时和总完成率同报；更早失败不构成加速。吞吐提速与单任务 runtime 提速分别说明，必要时少量串行复核而不要求所有任务再排成单核长队。

## 9. 指标、统计和提前冻结的判定规则

### 9.1 性能验收：runtime 优先，资源与质量受保护

主指标是**计入初始化成本的总 runtime，相对同条件 Default 至少下降 5%，即 T_GNN/T_Default≤0.95**。在每族共同成功配对先计算几何均值比，再对族等权汇总；共同成功数量及全部成功/失败计数同时给出，成功率保护先于速度结论。开发 pilot 和最终未见族分别验收，先验划定的 H/Z、压力/常规分层分别报告。

- 预算内成功率不得低于 Default；报告新增修复和成功损失，不能把失败的耗时变短算作收益。基础设施缺测可能改变结论时不得判通过。
- 五个 seeds 的平均已测 Wmin 比不超过 1.03；CPD 与 WL 在共同成功条件的几何均值比均不超过 1.03。保护既看每个设计及预登记分层，也看总汇总，不允许总体均值掩盖 arm_core 式严重退化。
- pilot 两固定宽度完成时可以判定压力点结果与运行完整性；完整性能通过仍须等待单独冻结的五 seed 边界扫描及受控计时，不把未知 Wmin 保护自动填为通过。
- checkpoint 从预登记 validation 候选中按真实 VPR 保护条件及总时间选择，详见第 6.2 节。测试阶段不选 checkpoint、不按测试族选择方法，不因测试 QoR 好看而替换主指标。
- 若无配置满足门槛，记录性能未通过；接口、架构真实性和工程复现可以独立通过。允许预先说明的一次负面/探索性冻结测试，但不能称已验证性能改进，也不自动展开全部消融。

族级配对置信区间与每族原始结果同时给出；达到点估计门槛但证据不确定时，只称开发信号。四个开发族的 seeds/架构再多也不能替代新族最终验证。

### 9.2 真值、代理与失败语义

- 真值：实际 route 成功、最终 routed CPD/WL、各阶段时间/迭代和真实 XYZ 路由资源使用。跨层报告独立 Z pool 占用、方向/segment、热点 cut、关键路径跨层代价及层资源利用。
- 代理：粗路径负载/容量、P95/P99/CVaR、几何关键网距离、AP 原语需求/容量、初始层/区域保持率。代理溢出或下降均不等于详细 packing/路由失败或改善。
- 成功路由的 overuse 通常为零，不把它包装成超容量拥塞；若报告 occupancy/capacity 分位数，注明统计对象。正常路由失败的 overuse、候选 demand proxy 和成功资源利用分别保存。
- 状态至少区分 `success / unroutable / packing_or_placement_failure / decode_failure / timeout / resource_budget_exceeded / infrastructure_failure / unsupported`。超时与环境错误不直接归为物理不可布通。OOM/配额等按原因审计：共同基础设施故障不能当模型负标签；某方法超过冻结资源预算则是方法预算失败，保留在成功率分母，不以环境错误排除。缺库等修复后按相同签名重试。
- 同条件方法采用相同 Default-only 校准的后端预算，初始化预算另计且先冻结。`timeout` 在预算内成功率计作未成功，仍不提供确定物理阈值；基础设施故障最多同签名重试一次，未知结果报告上下界/缺测，不能静默删除。
- 失败 CPD 不填零；共同成功 QoR 的选择偏差和样本数显式给出。必要 fallback 记录触发原因、原方法状态和失败尝试的全部时间，不能无声回退 Default 后把它当 GNN 成功。

### 9.3 首批可回答的问题与统计单位

三组先比较 M11−B0、M11−B1，再检查方法收益与 H、Z 及预登记资源压力的交互，同时核对阶段耗时、迭代和垂直供给使用的解释是否一致。由于没有逐模块消融，不从三组结果直接推断 Tail/RRG GNN/layer head 的独立贡献。

族内聚合后给族级配对 bootstrap 95% 区间及逐族结果。seed、候选、宽度不是独立设计，训练 seeds 也不乘进族样本量。只有四族时 bootstrap 只作描述；即使四族同向，双侧精确符号检验最小 p 值仍为 0.125，不能仅凭区间或大量 seeds 宣称强泛化。未来组件归因单独预登记并处理多重比较，未执行的 R/T/C/L/I 面板不产生结论。

## 11. 必须回答的问题与未通过时的处理

1. **学习初始化本身能减少后续工作吗？** 看 M11 对 B0/B1 的计入初始化总时间、成功率与资源/QoR 保护；再看 GP、APPack、详细布局、路由分别省了什么。不能仅因解码快或生成成功就称性能改善。
2. **为什么需要 3D 联合供需建模？** 看固定总资源/垂直供给的 H×Z 配对以及真实跨层 pool 使用。只在覆盖条件内解释，不能把层间放了节点等同真实跨层路由已经改善。
3. **收益是否可迁移？** 开发四族、已查看的继承 holdout、冻结后的全历史未见族分别报告。更多 seeds 不增加独立族数量；未执行模块归因时不声称某个特征单独有效。
4. **代价能否接受？** 看冷启动/常驻计费、各设计严重回退、失败/回退次数、平均 Wmin 与 CPD/WL；成功子集的快不能抵消新增失败。
5. **工程资格和算法性能各通过了什么？** 新 XYZ native GP/APPack 接口、架构真实性、数据契约可独立验收；整体收益仍以第 9 节门槛为准。

若候选中已有稳健收益而部署生成器学不到，先查正负收益监督、选模及稀疏反馈；若连训练条件的候选都没有收益，先查解码集中、层分配动作及 GP 接入，不直接归因于测试族不足。若只有训练族有效，再检查覆盖与泛化。若真正后端资格失败，记录工程阻塞，不作为 TailRisk/GNN 无效证据。

最多两批预登记学习配置后仍无真实收益，就归档当前方法未通过并依据明确诊断决定下一版本，不无限追加候选、启发式修正、温度或层数。原 2D v6.9 负结果保留，不能为进入 3D 倒推修改验收口径。

外部方法复现仍按 [独立补充协议](EXTERNAL_COMPARISON_PLAN_2026-10-23.md) 准备，原工具与统一后端适配分开命名。补充协议尚未同步到本轮三臂/五 seed/runtime 主指标前，不派发其中旧大矩阵；外部安装不阻塞当前主链。未完成的对比明确列出，近似硬件的时序差异不冒充同器件算法增益。

## 12. 当前并行准备与学习队列

按 [准备期计划](PRE_GNN_EXECUTION_PLAN_2026-10-23.md) 推进四条泳道。已经完成且签名一致的旧资格不重跑；新的 GP 初始化接口仍需独立证据，不以旧 packed-cluster+SA 结果顶替。

| 泳道 | 第一批任务 | 交接条件 |
|---|---|---|
| A：后端 | 隔离 combined patch、XYZ hook/checksum、最多 24 次新 GP 核心资格、旧 2D 回归 | 初值真实消费且 native solver 继续，器件/层/路由检查完整后冻结 |
| B：数据/架构 | 全历史暴露清单、H×Z 真 RRG 审计、Default 两宽度校准、独立 Wmin 网格、少量 raw 教师 | 支持范围、架构/数据哈希和任务表完整，进入教师/反馈批量采集 |
| C：模型 | 固定 tile 叶区域与层次图、layer+leaf 联合选择、必要层容量保护、快速 XY/有限密度处理、权重映射 | 训练/部署对象一致，真实反馈能更新生成器，验证选模使用 VPR 结果 |
| D：评测/资源 | 三臂 480 pilot、状态分类/续跑、五 seed Wmin 汇总、受控并行计时、依赖感知存储回收 | 首批任务即可检查完整性、开销和比较规则，无需等跑完再补脚本 |

A/B 通过后，CPU 采教师与真实反馈，GPU 单独预训练/微调，再回 CPU 做开发 pilot、边界扫描和受控计时。CPU/GPU 阶段不能串在长时间 GPU 闲置的实例里等待。每阶段有独立完成标记及输入签名，续跑复用已成功运行和正常预算结果。

P0 接收的是 v6.9 工程契约和已核验性能结果，不再等待“2D 必须获益”。模型、budget 与三臂开发结论冻结后才在全历史未见设计上运行 P4；原 14 臂、固定低密度泛化及完整外部支线均需新的显式派发表，不属于当前准备队列。

商业轻量支线沿用一档器件/三个开发设计的资格与 Default 参照；RapidWright/E4 和原 512 次完整扩展仍推迟。该支线耗时与架构差异单列，不阻塞主线，也不能替代同器件的 GNN 对照。

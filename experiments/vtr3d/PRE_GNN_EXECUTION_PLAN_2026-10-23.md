# 3D 学习初始化：准备、接口验收与首轮实验执行顺序

初版：2026-10-23；修订：2026-10-25。状态：**A 新 GP 核心资格与 B 小器件 H×Z 审计已完成；真实小模型已训练并部署，C 自然设计难度校准、正式教师库及效果验收仍待服务器运行。** 结果见 [准备实验报告](RESULTS_V7_PREPARATION_2026-10-25.md)，分阶段命令见 [服务器入口](../vtr/tailcompile_v7_3d/README_SERVER.md)。保留原文件名以维持已有链接。

依据：[更新后的 3D 主协议](EXPERIMENT_PLAN_3D_V68_2026-10-23.md)、[2D v6.9 正式计时结果](../vtr/tailcompile_v69/runs/runtime_001/timing/paired_001/runtime_report.json)、已有 3D 报告及固定后端源码。[外部对比协议](EXTERNAL_COMPARISON_PLAN_2026-10-23.md)中的旧主矩阵和验收门槛需在正式执行前协调；本次准备和三组内部 pilot 以本文及更新后的主协议为准。

本阶段目标：**准备真实的层间资源及垂直供给场景，验收 APBlock→原生 3D GP→APPack 接口，再直接检验学习的 layer＋XY 初值能否减少后续工作。**进入 3D 的前提是工程契约冻结，不要求 2D 必须先取得性能收益。

## 1. 2D 已结束本轮评估，3D 按工程门槛推进

- **2D 工程基础可承接，整体性能目标未通过。**v6.9 完成 640 次 feedback、320 次扫描和 80 次正式计时；跨设计等权总时间增加 38.01%，纯 VPR 增加 2.66%，计时条件 Default 为 40/40 成功、GNN 为 34/40。不能继续以“等待 2D 性能验收通过”作为 3D 前置条件，也不能称 2D 已证明泛化加速。
- **局部可行性有证据，适用范围需保留。**LU8PEEng/w180 五 seeds 的总时间均降低，几何平均总时间下降 3.36%，CPD/WL 分别增加 1.67%/3.23%，未达到既定组合门槛；训练中筛选的 bnn/lenet 候选分别下降 5.67%/22.52%，属于事后选择的开发证据。
- **不必等待 3D 模型性能验收**：后端正确性、架构/RRG、Default 基线、原生 GP 教师、外部工具资格、商业 Default 对标。
- **仍须等待输入契约冻结**：批量数据需要明确 backend/architecture/schema 哈希。模型未验收不妨碍冻结一个隔离的工程候选，但不能拿不断变动的后端批量造数。
- **必须等待模型与协议冻结**：正式留族测试和性能主张。首轮开发先跑三组比较；R/T/C/L 完整消融留待已有明确收益后按问题需要追加。

建立隔离的 3D 实现，保留 2D release、安装和 checkpoint。若只更换权重，已签名的结构图/原始教师通常不必重采；若改变逻辑单元、映射、后端或图语义，逐项判定缓存失效。旧二维权重只能按字段/形状映射作为训练初始化，不能改名后充当已验收的 3D 模型。

本轮必须吸收的实现经验：

- v6.9 快速解码约为 0.005～0.256 秒，但进程启动、导入和包装额外约 1.5～2.4 秒；应设计常驻 worker，并同时报告冷启动与常驻模式成本。四个测试设计的 GP/布线阶段仍未稳定变快，不能只减去启动成本就宣布有效。
- 软密度后独立选择区域出现需求集中：LU8PEEng/w156 约 47.8% 的 LUT 需求落在一个叶区域。这是 AP 需求/容量代理诊断，不是最终放置非法的证明。3D 必须独立保护层资源兼容、固定约束和必要层总容量，不能直接把两轮软调价＋逐点 argmax 用作层分配。
- 160 个训练条件中仅两个替换为真实收益初值，拒绝候选未直接形成负收益监督，checkpoint 又按教师重建 loss 选择，最佳 epoch 为 1。3D 需利用候选间正负收益信息更新实际生成器，并以开发验证集的真实总耗时和 QoR 保护选模；教师监督保留为稳定项，不等于 runtime 目标。

## 3. 六项工作及明确出口

### A．非零 layer 的原生学习接口资格——最高优先级，不需要训练

**回答：**将来 GNN 给出的 XYZ 初值，能否真正进入原生 GP，再走 APPack、SA 和 router？

- 固定基础 commit `40f8d19708b0b60e2aa04452deb1cfed68d96b0b`；独立构建 heterogeneity v2＋新 3D warm hook，保留准确补丁/二进制哈希。
- 扩展 APBlock/fixed XYZ/schema/checksum；使用 native GP 回放与明确改变层的测试初值 A/B，不训练网络、不调代理目标。
- 按主协议 P1，4 个 case×Default/A/B×2 个工程 seeds（本包固定 701/702）＝**24 次首轮核心 P&R**。覆盖同构、异构、混合硬资源/固定约束、至少一个自然开发设计，以及确需跨层连接的网。
- 检查初值消费、原生 solver iteration 1 继续、非零 layer、APPack 前后同一 grid、固定节点不变、最终位置/路由合法及实际跨层资源使用。
- 新 binary 运行已有 7 项单层回归；另做旧/新 binary×冷/暖初始化的 4 次单层 native-GP 配对，总计至多 **11 次单层回归**。旧 SA/flat-recon 回归不能单独证明 GP hook 兼容。

**出口：**通过即冻结工程版本，不要求 A/B 比 Default 更快。最多两轮 correctness 定位；仍失败就报告具体路径，不用旧 `.place`/SA 路径顶替，也不调退火温度。

输出：`backend_manifest.json`、`backend_trace.json`、资格覆盖表和故障最小复现。工程测试初值不作为 GNN 性能样本。

### B．H×Z 架构与真实供给审计——与 A 并行

**回答：**我们是否真正构造了“资源总量不变、层间分布不同”和“Z 供给总量不变、位置不同”的四格？

- 生成 `H0Z0/H0Z1/H1Z0/H1Z1`；同 primitive、固定 grid、全局 CLB/FF/DSP/BRAM/IO 总量匹配。集中 Z 的位置由预登记几何规则选定，不能按实际路由热点挑选。
- 按实际 RR nodes/edges 核对独立共享资源池、方向/segment/switch 类别、pin access 和已知断连；不以 XML 注释或 edge 总数代替容量。
- 审计每个 grid/width 下横向与垂直资源是否耦合变化；若增大 channel width 同时增加 Z 资源，只能把扫描解释为该器件族的联合资源变化，不能宣称单独节省横向资源。
- 区域图适配为每层每 4×4 tile 一叶，保留跨区共享池与层次索引。沿用旧池计数内核不代表旧区域划分、资源模式或多高度支持已经可直接继承。
- 最小审计先取一个固定 grid、W=64/128 两点：4 架构×2 widths＝**8 份真实 RRG 导出**，不是 8 次完整 P&R，也不是覆盖所有配置。width 若不被架构接受，在任务启动前修订并记录。
- SHA/OR1200 若沿用不同 grid，则两套都要审计，起步为 16 份；后续每个新 grid/width 都需相应审计，可从校准任务共享导出，不重复生成相同签名。
- 先完成 D=100% 主四格。D=50% 的生成/计数单测可以并行，但批量低密度实验留到主四格稳定后。

**出口：**资源账本、真实 Z 池配对和 RRG hash 完整。若该版本无法生成等容量的位置配对，两轮定位后明确修订研究范围；不能偷换成“同时减少且集中 Z”。

输出：四格 XML、`architecture_audit.json`、缓存索引、同配置资源差异表。当前构造基于固定版本 Hecate 3D 架构，不把 2D COFFE 模型误称为已存在的同一 3D 器件。

### C．Default-only 的 3D 难度与 H/Z 对照——A/B 通过后立即可跑

**回答：**默认后端在四格中的真实成功/失败边界在哪里，H 与 Z 怎样影响结果？这不是 TailCompile 有效性实验。

- 起步只用已见 train 族 SHA、OR1200；目标架构下统一映射/核对 primitive，不能把旧 2D packed `.net` 直接搬进来。既有 BLIF 若复用，必须保留转换、功能检查和哈希。
- 路线固定为关闭 hook 的原生 GP→APPack→SA→route，不能复用历史 SA-only 的 112/176 宽度充当新链路边界。
- 按主协议固定网格 `32,48,64,80,96,128,160,224,320,448` 顺序，使用 calibration seeds 501/502。
- 四架构共用同一 design 的 `W_ref/W_stress`；前者取首个 8/8 正常成功的网格点，后者按主协议在更小正常失败点中选成功率最接近 50% 者。未测更小点不能声称找到首个参考点。
- 总上限 **2设计×4架构×2seeds×10宽度＝160 次**；不是必须跑满。先提交最多 48 次的队列窗口，审查正确性/成本后才续派，找到所需点即停止。自动派发不额外扩展网格；删失按主协议报告。
- 记录 route 状态、CPD、线长、实际跨层资源使用、按层资源利用率、时间/RSS。成功路由 overuse 为零不等于没有热点；供需代理与真实路由指标分表。
- 超时、环境错误及 packing/placement failure 单独分类，不作为“正常不可布通”定位边界；资源/配置不合法先处理资格，不能靠增加宽度掩盖。

**出口：**冻结的条件清单和四格 Default 表，供未来所有方法直接配对。四格没有明显差异也如实保留，不重新按效果选 Z 位置或把 SHA 的两份近似相同结果当独立证据。

SHA 主要是控制样例，OR1200 的硬资源利用率也有限；此阶段只建立流水线与难度测量。并行盘点其余 train 族的映射需求，按预登记资源/规模规则选后续硬资源负载，不以“某模型在它上面赢了”选样本。

### D．原生 3D GP 教师与训练数据审计——不依赖 GNN 权重

**回答：**能否获得训练所需且没有测试泄漏的 APBlock 图、器件图和一致的 XYZ 标签？

- A/B/C 的 backend、架构和宽度已冻结后，使用 train 的 SHA/OR1200、teacher seeds 511/512。
- 先只做 H0Z0：2设计×1架构×2宽度×2seeds＝**8 次**；数据合格后扩到四格，总计 **32 次**（不是另加 32）。
- 上述次数以 C 已取得两个有效冻结宽度为前提；若为删失样本，按主协议记录缺失条件，只采可用的已冻结点，不能虚构 W_stress/W_ref 凑齐数量。
- 保存 pre-GP 无 movable teacher 坐标的结构输入、原始 GP 连续 XYZ、原生层映射规则、完整后端结果和签名；不平均不同 seed 的层/坐标。
- 当前优先保留 raw teacher。投影规则未冻结时只做诊断，不能称为最终训练标签。投影派生文件另存，并记录 layer 变化、XY 位移、固定约束和聚合需求溢出。
- 稀疏器件 embedding、图缓存、容量解码和输出 parser 的 CPU 单测可先实现；B1 采用固定均匀分数，禁止借机引入新的启发式优化。
- 同时建立联合 `(layer, leaf)` 与叶内 XY 的实际生成器接口，固定 layer 来自离散区域选择，原生 GP 后续可继续优化 Z。保留 molecule/RAM-group 原子性、fixed XYZ、层资源兼容与必要层级容量上界；层内 XY 使用快速输出和有限密度修正，避免把全叶精确 packing 解码重新放进生成关键路径。上界仍是 packing 代理，最终合法性由 APPack/VPR 检查。
- 教师预训练完成后，用 train 候选的真实相对收益更新生成器：完整保留正收益、负收益、失败及超时记录，不能只把两个优胜候选替换为教师就称已充分进行 runtime 训练。具体蒸馏/可训练代理、权重、候选数和反馈预算在批量采集前冻结；若使用评分器，说明它怎样实际更新部署生成器，不把评分器训练当作坐标 head 改进。
- 教师验证 loss 用于诊断；checkpoint 依据开发验证集固定任务的真实总耗时及成功率、资源/QoR 保护规则选择。测试结果不参与选模，也不对 VPR 假设可直接求梯度。

**出口：**可读、可重建、标签与结构分离的第一批数据；不是“GNN 已完成 3D 迁移”。20 train 族全量教师暂不一口气派发，先等工程候选和接口稳定，防止重复造数。

### E．轻量商业参照——独立于 3D 学习，服务器条件允许即可做

采用最新决定：**VTR 近似 7 系列＋Vivado 2022.1；不接 RapidWright。**本轮是开发参照，不冒充精确商业模型校准或未见设计泛化实验。

1. 服务器确认一个完整 XC7A35T part（package/speed/temperature grade）可用；本地固定 `7series_BRAM_DSP_carry.xml` 的 `XC7A35T-like`、W=190、clustered routing。未取得服务器环境/part 证据前，本地只能准备脚本与 VTR 一侧。
2. 三个功能小例：LUT/FF（含 carry）、BRAM、25×18 乘法；每例各跑 VTR/Vivado 一次＝**6 次资格 P&R**。至少一个例验证 OOC place→route→STA，而非仅综合。语义/寄存配置、资源模式、时序和 DRC/unconstrained 异常都记录。
3. 预登记三个开发候选：SHA、OR1200、stereovision0，均为当前 train 族。按共同功能、工具支持和容量资格筛选，缺项记录；备选顺序为 ch_intrinsics、reduction_layer，不按 CPD 或胜负替补。不要假定这三个例本身已覆盖 DSP/BRAM，也不要为了填满表单方缩小设计。
4. 共用 RTL/参数、一个目标周期（先冻结 10 ns）、Vivado 默认策略；VTR 用 501/502 两个开发 seeds。因此三个合格设计的 **Default 对标＝3×(2次VTR＋1次Vivado)＝9 次**。
5. 现在只填 Vivado 和 VTR Default 两列。3D 学习链路工程验收、7 系列需求/供给 adapter 合格且待比较模型冻结后，同条件再补 3×2＝**6 次 TailCompile**；旧启发式不得占据这一列。补列不要求 2D 泛化性能已通过。

**出口：**资格与商业参照表、资源差异、时序模型限制和可复现输入。当前 6+9＝15 次，模型到位后再 6 次；3–5 个设计的上限扩展须事前登记，首批固定为 3 个。

VTR 一侧采用未来 Tail 行相同的 native GP→APPack 路线，必须先通过该架构资格，不拿传统 pack/SA 路线无标注顶替。OOC 时钟源/BUFG、IO 评价范围、latency、约束和映射配置事前冻结。需要切 routing mode、XML 或行为相关 backend 时，先修订协议并按新签名重做整组必要基线；不能只给 Tail 改配置。

这 3 个小例只是功能/明显异常筛查，不等于原完整协议 C1 的 24 实例留出校准，也不能据此宣称 DSP 时序可信。DSP 原模型已知不准确，相关绝对 CPD/频率必须标模型受限；不拟合 benchmark 使之接近 Vivado，不报告精确 Fmax 或算法胜过 Vivado。

当前不做第二器件档、多策略、多目标周期、7 系列衍生 3D 或 E4/RapidWright。已见开发设计的表不能日后改称 final test；正式未见商业表如提前执行，QoR 必须封存到模型冻结之后。

### F．Beyond Flatland 作者流程资格——有闲置资源时并行

- 固定作者代码、依赖、原始 baseline/full 开关及命令；不默认移植所有优化到本项目。
- 两个开发设计×两种架构×作者 baseline/full＝**最多 8 次首轮 P&R**；先核查作者原架构能跑，再审计与主架构的共同支持范围。
- 若有环境/兼容问题，只做一轮有限复验。`unsupported` 与正常 `unroutable` 分开，不能据不支持输入宣称其效果差。

**出口：**版本、命令、支持矩阵和后续公平比较条件，不要求此时已经战胜作者流程。完整 E1 适配和 E2 正式大表等主后端冻结后执行；该支线不阻塞 A–D。

## 4. 实际排程：现在启动什么，不一次跑满所有表

### 指标和通过条件：runtime 优先，资源与质量受保护

- **总 runtime 至少下降 5%（`T_GNN/T_Default ≤ 0.95`）**，计入推理、约束/密度修正、解码、写文件及后续 VPR；可复用 RRG 构建/编码成本单列。默认主验收采用单次冷启动；常驻 worker 独立给表，并计入服务建立和冻结调用次数的摊销。若以常驻部署为主，须在 P0、运行前另行登记，不能看到结果再切换。不把实际发生的导入/初始化成本静默删去，Default 包装成本同口径计入。
- **成功率不下降**，平均 Wmin、CPD、WL 的退化均不超过 3%。保护在预登记的逐设计/分层比较上检查，同时报告跨设计等权汇总；不能让某设计的明显损失被几何平均掩盖。成功样本的 QoR 与全体成功/失败/超时同时报告。
- **平均 Wmin＝五个 seeds 各自最小已测试成功宽度的算术平均。**两个 pilot 宽度仅用于压力点和参考点对照，不足以确定此指标；另行以 Default-only 校准后冻结的边界网格完整扫描，所有方法和五 seeds 使用相同网格。保留非单调、左右删失及未知状态，不把超时记成正常不可布通，也不把没有成功宽度的 seed 从均值中悄悄删除。
- 每个宽度都重新执行 GP 的结果是“该算法在冻结资源网格上的需求”，不是固定布局的纯 route 阈值，更不是物理最小值。报告每宽度成功率和原始状态，避免宽度摘要掩盖非单调性；同时列明横向宽度与 Z 容量是否耦合。
- 同步记录 GP、完整合法化/APPack、详细布局、布线阶段的时间与迭代量，以及层资源利用率、真实跨层 wire 使用和关键路径跨层代价。代理下降或布局保持率不能代替真实加速。

## 5. 执行、存储与最终交付

CPU 与 GPU 阶段分开：资格、教师、feedback P&R、评测与计时放 CPU；训练放 GPU。CPU 默认请求 **32 并行**，按 CPU 配额和实测峰值内存约束有效并发，常用 16～32；准备、RRG 和候选生成分别显式设置上限并输出，不再静默固定为 1～2。内存不足时打印降并发原因，不能为填满核数重跑无必要任务。

runtime 采用受控并行配对：每个 VPR 固定一个物理核、内部一个 worker，避开超线程兄弟核；同一条件三方法同核先后运行，按预登记的 ABC/ACB/BAC/BCA/CAB/CBA 平衡次序轮换，两方法子实验采用 A→B/B→A。不同条件分波并发，记录 host/boot、CPU quota、物理核、实际并发、内存限制和顺序。不同并发/串行会话分别汇总；扫描耗时不直接混作正式加速比。

各阶段输出任务总数、复用数、运行数、完成数与心跳；断点重启按输入/后端/模型/参数哈希复用成功和正常不可布通结果。环境错误、配额失败和超时单列并按预登记规则重试；OOM 等须区分共同基础设施故障与某方法超预算，后者保留为方法失败并计入成功率分母。未知结果不得当成功缓存。计划变更只失效受影响缓存，不清空整批成功记录。
